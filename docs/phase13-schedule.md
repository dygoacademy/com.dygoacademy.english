## How the sessions work

A **session** = one fresh Claude conversation that fits in one usage window. Sizing rules used below:

- **One task slice per session**, about 5–12 files touched, ending in **one or two commits**. Nothing that needs the whole repo in context.
- **Start cold, cheaply:** read only `CLAUDE.md`, this file, the notes sections named in the row, and the files listed. Don't re-read the handover or design files beyond the screens named.
- **Commit after each sub-step** (master rules: Change Log entry, exact paths, `phase13: Sx …`). If the limit hits mid-session, the work so far is safe.
- **End every session** by ticking the row here and adding one line to the *Session log* below: what's done, what's next, anything blocked. The next session starts from that line.
- **Never** run `next dev` in `com.dygoacademy.frontend`, never touch auth/billing/SRS scheduling. Deploy only via `deploy/request.md` where a row says **Deploy**.
- **Gates (G)** need Dylan (a device check or a decision). The session before a gate stops there.

Start prompt for each session (copy, fill in Sx):

```
Phase 13, session Sx. Read CLAUDE.md, docs/phase13-schedule.md (row Sx and the
Session log) and the notes sections it names. Do only Sx, commit after each
sub-step, then update the Session log and tick the row. Stop at the end of Sx.
```

The backend endpoint is built with a `MockSpeechChecker` first.
- **Edge Function → NestJS**: the handover's `supabase/functions/speaking-check` becomes a route in the backend speaking module (the repo has no Supabase functions; master rules 1–3).
- **SP2 v2**: countdown 3 · 2 · 1 (~0.9 s a step, tap to skip) → beep + vibration → keep audio from ~150 ms after the beep; auto-stop after ~2 s of silence after speech; no speech 8 s after the beep → "We couldn't hear you" + Record again; safety cap 30 s; elapsed time only (no target).
- **SP3 v2**: opens at once after stop; waveforms and Play Native / Play You work straight away; result area **checking** (shimmer, "Your recording is checked, then deleted.") → **done** (marks: fine, `MIT is too soft`, dashed + struck `missing`, `heard "affects"`, amber bands, stage, tip) or **failed** ("Couldn't check this one", Check again / Record again). Timeout 8 s → failed. Marks `rushed` / `slow` go; `unclear` (with `heard`) and `extra` (logged only) come in.
- SP1 and SP4 look unchanged. New copy keys: handover §8 (`getReady`, `countdownHint`, `startingSoon`, `pauseStops`, `checking`, `privacy`, `failed.*`, `notHeard`, `mark.missing`, `mark.heard`, `tip.also`).
- **Match the canvas 100% (`docs/design/garden/README.md`).** The speaking screens follow the same rule as every garden screen: the canvas is the source of truth, checked by pixel diff (≤ 0.5% per screen, only font anti-aliasing allowed), exact values read from `reference/<name>.html`, never from eyeballing.
